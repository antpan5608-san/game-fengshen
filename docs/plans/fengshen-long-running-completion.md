## 3. 推荐界面方案

采用**敌左我右的经典回合制战场，加独立队伍状态与操作区**。这是针对本作的设计选择；参考官方回合制游戏将敌我、指令、状态和能力说明分区的做法，而不是照搬其他游戏的战斗机制。[《Bravely Second》官方手册，第22节](https://www.nintendo.com/eu/media/downloads/games_8/emanuals/nintendo_3ds_2/bravely_second___end_layer/ElectronicManual_Nintendo3DS_BravelySecondEndLayer_EN.pdf)

| 区域 | 展示与操作 |
|---|---|
| 顶部提示 | 当前操作角色、选中动作、需要选择的目标 |
| 中央战场 | 左侧敌人、右侧队友常驻显示；Boss 独立留位 |
| 队伍状态区 | 每人一张卡：名字、HP/MP 数字与条、异常状态、当前行动标记 |
| 指令区 | 攻击、法术、物品、逃跑；信息入口单独放置 |
| 行动提示 | 独立短提示与可展开记录，不与队伍状态混排 |
| 详情层 | 敌人、角色、技能或物品详情按需打开，可滚动 |

**战斗画面**

- 移除横跨全屏的普通敌人血条，改为敌人附近的紧凑标签和血条；同种敌人用稳定实例编号区分。
- 队友常驻战场，行动者和目标使用轮廓、箭头及文字标识；伤害和治疗数字显示在实际目标附近。
- 复用原版已核素材，保持像素比例、锚点与清晰缩放；缺少专用战斗动作时先使用真实静态姿态，不编造角色立绘。
- 背景填充战场区域，保留合法原版黑底场景；通过布局解决无意义留白，不用无来源背景冒充原版场景。
- HP、状态和动画读取当前行动快照，不能提前显示后续结算结果。
- 默认先选动作，再点合法目标提交。未选动作时点击敌人只选中查看；信息浏览不耗行动。无目标动作保留明确执行按钮。
- 不可用指令显示简短原因；只有实现并验证能力后才开放。胜利结果独立显示奖励、升级、掉落与保存状态。

**角色与装备**

- 队员选择改为头像加完整名字的卡片，避免“小龙女”等名字被挤成窄列换行。
- 属性页优先显示等级、HP/MP、状态、本级经验和距下一级经验，再分组显示战斗属性。
- 装备页展示当前装备与候选装备，明确标出属性前后差值、适用角色、槽位及不可装备原因。
- 详情滚动区与操作按钮分开，按钮不遮挡文字；预览不修改实际角色或背包。

**物品**

- 增加全部、药品、装备、特殊物品分类与名称搜索，默认展示实际持有物。
- 列表显示图标、完整名称、数量和当前用途；详情统一显示效果、合法目标、适用场景、消耗与使用限制。
- 区分原版不可用、当前条件不足和功能未实现，禁止统一显示模糊的“操作待接入”。
- 列表选择不消耗物品，明确使用动作才提交；地图和战斗使用条件分别来自现有规则。

**适配要求**

- 一至四名队友全部可见；大字体时使用两列状态卡和独立详情层，不靠缩小字号或裁切解决。
- 保留横屏安全区、刘海避让及统一命中布局。交互目标至少 48dp；重要文字采用实色底和足够对比度，状态同时使用图标与文字表达。[Android 触控建议](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)、[Xbox 游戏对比度指南](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102)
